# N 语言（V2）翻译器

基于《语言系统 V2 规则说明书》实现的 **N 语言**解析、检查与中文译写工具。
纯 Java、零第三方依赖，`javac` 直接编译，也提供交互式命令行。

N 语言是一门刻意设计的形式语言，六层结构：

```
CODE 编码 → WORD 词汇 → OPERATOR 算子 → FORM 形式 → EXPRESSION 表达式 → SEMANTICS 语义
```

本项目把这六层落成一条可运行的编译器前端，并加了一层中文渲染。

---

## 功能

| 功能 | 说明 |
|---|---|
| **例句库互查** | 75 组「中文 ⇄ N 语言」对照，输入任一侧得到另一侧 |
| **N 语言 → 中文** | 任意合法句子走真正的解析器，输出结构化中文 |
| **编码 ⇄ 词形** | `2004 ⇄ tapu`，非法输入返回 `null` |
| **静态检查** | 词法/语法/词典/绑定/签名/类型，十类诊断带行列号 |
| **交互模式** | 启动即菜单，中文或英文指令都认 |

## 快速开始

需要 **JDK 17+**（开发环境为 openjdk 23）。不需要 Maven、不需要联网。

```sh
git clone <你的仓库地址>
cd N语言
./run.sh
```

```
==============================================
    欢迎来到N语言翻译器！
==============================================
 2004 / tapu       数字 ⇄ 单词
 那只狗饿了。        中文 → N 语言（例句库）
 dapi(km m paku).  N 语言 → 中文
 测试 / test       查看 75 组例句对照表
 翻译 / translate   逐行翻译任意 N 语言句子
 帮助 / help       全部指令    退出 / exit  离开
----------------------------------------------
> 
```

### 在 IntelliJ IDEA 里

1. `File → Open` 选**项目根目录**（有 `pom.xml` 的那层）
2. `Settings → Editor → File Encodings` 三项都设为 **UTF-8**（源码含 `∀ ∃ ∧ ∨ ↔ ⊤ ⊥`，GBK 会直接炸）
3. 运行 `nlang.Main`，**不要带参数**，即进入交互模式

## 命令行

不带参数启动交互模式；带参数则执行单次任务：

```sh
./run.sh                          # 交互模式
./run.sh test                     # 打印例句对照表
./run.sh trans examples/basic.n   # 翻译文件
./run.sh trans -                  # 从标准输入读
./run.sh code 42C4B1             # → kinume
./run.sh word kinume             # → 42C4B1
```

`trans` 失败时不输出中文，诊断走 stderr，退出码 `1`。

## 例句库

75 组对照，全部通过静态检查。覆盖：集合关系、布尔属性、状态、动作、
空间、逻辑连接、量化、计数、iota、测量、时间作用域、事件与因果、信息对象。

匹配规则（**这是句子库，不是翻译器**）：

- 去空白、去句末 `。 . ？ !`、中文引号与英文引号等同、英文忽略大小写
- 整句匹配，换个说法查不到
- 查不到时会给"最接近的一句"提示

自己加句子，编辑 `src/main/java/nlang/SentenceBank.java`：

```java
add(list, "我的中文句子。", "tapa(kp m paka).");
```

## 实现范围

**已实现**

- ① 词法：最长合法记号、CV 词形、纯辅音算子、六种字面量及值域校验
- ② 语法：完整 BNF（含 `s(...)`、`z(...)`、`{x:T : F}`、`bb(...)`、`hh/hl/hv`、`hb…hd`）
- ③ 语义：词典与名称表分离、角色签名、变量绑定、类型匹配
- ④ 输出：中文译写
- ⑤ 工具：编码互转、例句库、括号预检查、多行输入

**未实现（有意留白）**

- 求值：模型、世界、参照时刻 `r`、`s` 的唯一性、`z` 的有限性、事件时间范围
  —— 规范 5.4/5.6 的 `IOTA_EMPTY` / `IOTA_MULTIPLE` / `UNDECIDABLE` 目前只有枚举，没有产生它们的代码
- 中文 → N 语言的自动翻译（只有例句库的整句匹配）
- 词典外置（目前硬编码在 `Lexicon`，规范要求带版本与迁移记录）

## 设计取舍

**为什么手写递归下降而不是 ANTLR**：这门语言的记号是"形状可分"的——含元音的才是词，
纯辅音串一定是算子，大写字母里类型（`A B N D E K M U S L O H`）与命题名（`C J Q R W X Y`）
字母表互不相交。词法器不需要回填，60 行足够；而且报错要落进规范定义的十类诊断，
生成器的错误信息还得再包一层。

**为什么例句库只做整句匹配**：中文与 N 语言不同构。一个中文句可能对应多个合法 N 表达
（语序、量化方式），反过来也一样。做真正的"中文 → N"需要先定一套翻译政策，
再写模板引擎，这不在当前范围内——所以宁可在查不到时明确说"没有这句"，
也不猜。

**为什么先查括号**：递归下降一旦少个括号，报错会漂到很远的地方。预检查让
"缺少 1 个 `)`" 变成第一等诊断。

## 规范书里的坑

实现时踩到并已处理：

1. **`㲗` 是缺字形**——PDF 里"逻辑等价"渲染成了 `㲗`，实际应为 `↔`。词法器接受 `↔ ≡ 㲗` 并归一。
2. **`62 ﬁ` 是连字**——应为 `fi`。
3. **编码与数值不同层**——`1004` 与 `n bapu` 无关；`8000–8004` 只是读音条目，出现在核心词项位置必须拒绝。
4. **`n` / `m` 不是类型转换**——`n bapu ∈ n bapa` 必拒。
5. **`H<B>` 全关**，且 `∃!` 与 `s` 的绑定类型不能是 `B`。
6. **优先级**——`¬` 最高且右结合，`→ ↔` 最低且左结合。
7. **句点 vs 小数点**——`3.` 是"数值 + 语句结束"，`3.5` 才是小数。
8. **变量带数字**——`x0`、`x12` 是一个记号，不能切成 `x` + `0`。
9. **量词只绑定自己括号内的变量**——所以 `∃y:K` 里引用 `x` 时，`x` 的量词必须把它包住。
10. **"没有 / 未报告 / 未知 / 未定义"是四件事**——求值器要分别建模。
